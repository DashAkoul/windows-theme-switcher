## ۱. باگ‌ها

### B1 — کانفیگ با JSON معتبر ولی مقدار نامعتبر، اجرای برنامه را کامل مسدود می‌کرد — **بحرانی**

`AppConfig::load` فقط خطای *parse* را بازیابی می‌کرد. اگر فایل JSON سالم بود ولی مقدارها نامعتبر بودند
(مثلاً `name` خالی یا `wallpaper` نسبی، که با ویرایش دستی یا نسخه‌ای با schema متفاوت رخ می‌دهد)،
`validate()?` خطا برمی‌گرداند، `setup()` هم آن را بالا می‌فرستاد و `build(...).expect(...)` پنیک می‌کرد.
نتیجه: برنامه هیچ‌وقت بالا نمی‌آمد و راه بازیابی هم نبود جز حذف دستی فایل.

**رفع:** مقدارهای نامعتبر هم مثل JSON خراب رفتار می‌کنند: فایل به `config.json.invalid` پشتیبان‌گیری و
config پیش‌فرض نوشته می‌شود. تست: `load_valid_json_with_bad_values_recovers`.

### B2 — Autostart بعد از جابه‌جا شدن exe به مسیر قدیمی اشاره می‌کرد — **متوسط**

`setup()` فقط *وجود* مقدار Run را با تنظیم مقایسه می‌کرد (`is_enabled() != setting`). اگر مقدار وجود
داشت ولی به مسیر قدیمی اشاره می‌کرد (نصب در مسیر دیگر، جابه‌جایی بین نسخهٔ نصب‌شده و portable)، هیچ
بازنویسی رخ نمی‌داد و ویندوز در هر بوت یک exe ناموجود را اجرا می‌کرد.

**رفع:** تابع `autostart::sync()` اضافه شد که مسیر را هم مقایسه می‌کند. تست: `sync_rewrites_a_stale_path`.

### B3 — تیک «Start with Windows» در منوی tray به‌روز نمی‌شد — **متوسط**

`toggle_autostart_inner` تنظیم را عوض می‌کرد ولی `tray::refresh` را صدا نمی‌زد، بنابراین
`CheckMenuItem` تا رخداد بعدی (تغییر تم) مقدار قدیمی را نشان می‌داد.

**رفع:** refresh در انتهای تابع.

### B4 — `save_settings` کانفیگ را قبل از Run key ذخیره می‌کرد — **متوسط**

اگر نوشتن Run key شکست می‌خورد (سیاست سازمانی/آنتی‌ویروس)، تابع خطا برمی‌گرداند **بعد از** اینکه
`config.json` ذخیره شده بود: فایل می‌گفت autostart روشن است، رجیستری می‌گفت نه، و state در حافظه هم
مقدار قدیمی را داشت.

**رفع:** اول Run key، بعد ذخیرهٔ کانفیگ.

### B5 — `hex_to_abgr` با رشتهٔ ۶ بایتی غیر-ASCII پنیک می‌کرد — **بالا (مسیر محافظت‌شده)**

`&h[0..2]` روی مرز کاراکتر فرض می‌کرد که هر بایت یک کاراکتر است. ورودی مثل `"€€"` (۶ بایت، ۲ کاراکتر)
باعث پنیک «byte index 2 is not a char boundary» می‌شد و با `panic = "abort"` کل برنامه می‌مرد.
امروز `validate()` قبل از آن اجرا می‌شود، ولی تابع `pub` است و یک تغییر کوچک می‌توانست مسیر را باز کند.

**رفع:** `is_ascii()` قبل از برش. تست: `hex_to_abgr_rejects_non_ascii_without_panicking`.

### B6 — فلگ `APPLYING` با پنیک برای همیشه گیر می‌کرد — **پایین**

اگر `apply_profile_inner` پنیک می‌کرد، فلگ هیچ‌وقت آزاد نمی‌شد و همهٔ apply های بعدی بی‌صدا state فعلی را
برمی‌گرداندند (یعنی دکمه‌ها دیگر کار نمی‌کردند).

**رفع:** گارد RAII (`ApplyGuard` + `Drop`).

### B7 — خطای `GetMessageW` مدیریت نمی‌شد — **پایین**

`GetMessageW` در خطا `-1` برمی‌گرداند که `as_bool()` آن را «درست» می‌بیند، بنابراین یک `MSG`
مقدارنشده dispatch می‌شد (رفتار تعریف‌نشده).

**رفع:** بررسی صریح `ret.0 == -1` و توقف حلقه.

### B8 — `LAST_SHOWN_MS` بعد از `set_focus()` ثبت می‌شد — **پایین**

`set_focus` می‌تواند همان‌جا رویداد `Focused(false)` زودهنگام را برساند، یعنی دقیقاً همان چیزی که این
timestamp باید جذب کند.

**رفع:** ثبت قبل از `show()`.

### B9 — نمونهٔ دوم، پنجرهٔ سیگنال دوم می‌ساخت — **پایین**

`start_monitor_thread()` قبل از بررسی `AlreadyRunning` صدا زده می‌شد، پس نمونهٔ دوم چند میلی‌ثانیه یک
پنجرهٔ `WTS Signal` دیگر ثبت می‌کرد که اجرای سوم می‌توانست آن را پیدا کند و پیام را به پروسهٔ در حال
خروج بفرستد.

**رفع:** ترتیب جابه‌جا شد.

### B10 — تست‌های autostart موازی روی یک کلید واقعی اجرا می‌شدند — **کیفیت**

`enable_disable_roundtrip` و `sync_rewrites_a_stale_path` هر دو Run key واقعی را می‌نوشتند و Rust
تست‌ها را موازی اجرا می‌کند؛ نتیجه: شکست متناوب (در اجرای تک‌تک پاس می‌شدند).

**رفع:** یک `Mutex` مشترک در ماژول تست.

### B11 — رویداد `theme-error` شنونده نداشت — **پایین**

tray هنگام شکست، `theme-error` منتشر می‌کرد ولی پنل فقط `theme-applied` و `system-theme-changed` را
گوش می‌داد؛ یعنی شکست کلیک روی tray فقط در لاگ می‌ماند.

**رفع:** `onThemeError` در `api.ts` و اشتراک در `Panel`.

### B12 — نسخهٔ mock در حالت مرورگر هاردکد `2.0.0` بود — **پایین**

**رفع:** `"dev"` (نسخهٔ واقعی از Rust می‌آید).

## ۲. امنیت

### S1 — خواندن اشاره‌گر دلخواه از `WM_SETTINGCHANGE` (کرش قابل‌القا) — **متوسط**

`wide_ptr_to_string` بدون هیچ اعتبارسنجی، تا ۲۵۶ کاراکتر از `lParam` می‌خواند. `WM_SETTINGCHANGE`
را **هر** پروسه‌ای می‌تواند به پنجرهٔ ما بفرستد (پنجره top-level و با عنوان ثابت پیدا می‌شود). با یک
`lParam` جعلی، برنامه دچار access violation و کرش می‌شد — یک DoS محلی ساده برای هر برنامهٔ هم‌سطح.

**رفع:** قبل از هر خواندن، ناحیهٔ حافظه با `VirtualQuery` بررسی می‌شود (commit بودن + قابل خواندن بودن +
محاسبهٔ طول مجاز از `RegionSize`). تست: `wide_ptr_to_string_rejects_unreadable_pointers`.

### S2 — CSP تولیدی بیش از نیاز باز بود — **متوسط**

مقدار قبلی شامل `ws://localhost:*`، `http://localhost:*`، `asset:`، `http://asset.localhost`، `blob:` و
`style-src 'unsafe-inline'` بود — بقایای نسخهٔ ۱ (پیش‌نمایش والپیپر و dev server). یعنی webview اجازهٔ
ارتباط با هر سرور محلی و بارگذاری تصویر از هر مبدأ asset را داشت.

**رفع:** CSP تولیدی به حداقل رسید:

```
default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self';
font-src 'self'; connect-src ipc: http://ipc.localhost;
object-src 'none'; base-uri 'self'; form-action 'none'; frame-ancestors 'none'
```

اجازه‌های مخصوص dev به `devCsp` منتقل شدند (فقط در `tauri dev` استفاده می‌شود). برای اینکه
`'unsafe-inline'` لازم نباشد، بلوک `<style>` داخل `index.html` به `public/boot.css` منتقل شد.
**تأیید:** پنل پس از تغییر CSP دقیقاً مثل قبل رندر می‌شود (رنگ‌ها و چیدمان یکسان، ۳۲۶ رنگ متمایز در
نمونه‌برداری، بدون صفحهٔ خالی).

### S3 — لاگ بدون سقف حجم — **پایین**

هر تغییر تم دو خط می‌نویسد و فایل هیچ‌وقت چرخش نمی‌کرد؛ در یک ابزار همیشه-روشن می‌تواند بی‌نهایت رشد کند.

**رفع:** چرخش در ۲۵۶KB به `app.log.1`. تست: `oversized_log_is_rotated`.

### نکات تأییدشدهٔ امنیتی (بدون مشکل)

- کلید خصوصی امضا هرگز در تاریخچهٔ git نبوده و در `.gitignore` است (`git log --all -- .tauri/*.key` خالی).
- آپدیتر: HTTPS + تأیید امضای minisign قبل از نصب؛ endpoint فقط `releases/latest/download/latest.json`.
- هیچ `ShellExecute`/`Command` با ورودی کاربر وجود ندارد؛ فقط URI ثابت `ms-settings:`.
- نصب per-user، بدون elevation؛ همهٔ نوشتن‌ها در `HKCU`.
- `dangerouslySetInnerHTML` / `innerHTML` استفاده نمی‌شود.
- capabilities حداقلی است (`core:default` + چند مجوز پنجره + `updater:default`).

## ۳. بهینه‌سازی

### O1 — فیچرهای بی‌استفادهٔ crate `windows`

`Win32_System_SystemInformation` و `Win32_System_Registry` در کد استفاده نمی‌شدند و حذف شدند.
(`Win32_Security` و `Win32_Graphics_Gdi` لازم‌اند: امضای `CreateEventW`/`CreateMutexW` و ساختار
`WNDCLASSW` به آن‌ها وابسته است.) نتیجه: زمان بیلد و سطح API کمتر.

### O2 — فیلد مردهٔ `isWindows11`

از Rust تا UI منتقل می‌شد ولی هیچ‌جا خوانده نمی‌شد؛ حذف شد (struct، types، mock).

### O3 — کد و کامنت مرده

کامنت orphan در `logger.rs`، تست بی‌ارتباط `tail_returns_last_lines` (تابع `tail` حذف شده بود)،
کامنت کهنهٔ «هر ۳۰ ثانیه» در `monitor.rs`، و تابع بی‌استفادهٔ `is_enabled` (با `cfg_attr` علامت‌گذاری شد).

### O4 — ساعت غیر-monotonic برای گارد focus

`now_ms()` از `SystemTime` استفاده می‌کرد که با sync ساعت ویندوز می‌پرد و مقایسهٔ مهلت ۷۰۰ms را
بی‌معنی می‌کرد. حالا از `Instant` استفاده می‌شود.

## ۴. ریسک‌های پذیرفته‌شده (بدون تغییر)

| مورد | چرا پذیرفته شد |
|---|---|
| Mutex در namespace `Local\` قابل squatting است | یک برنامهٔ هم‌سطح می‌تواند اجرای نمونهٔ اول را مسدود کند (DoS برای همان کاربر). استفاده از `Global\` نیاز به admin دارد و بدتر است. |
| مسیر والپیپر می‌تواند UNC باشد | کانفیگ در `%APPDATA%` فقط توسط خود کاربر قابل نوشتن است؛ کسی که آن را بنویسد از قبل code execution دارد. در UI نسخه ۲ اصلاً انتخاب والپیپر وجود ندارد. |
| بعد از اولین باز شدن پنل، private commit از ۲.۳MB به ۶.۹MB می‌رسد | باقی‌ماندهٔ runtime WebView2 در پروسه است و Tauri راهی برای آزادکردن environment نمی‌دهد. Working set همان ~۱۵۰KB می‌ماند. |
| broadcast تم ممکن است چند ثانیه طول بکشد | روی thread جداگانه و fire-and-forget است؛ UI بلاک نمی‌شود (اندازه‌گیری: apply در ۱ms). |

# پاس دوم بازبینی (نسخه ۲.۱.۲)

بازبینی دوم روی چیزهایی تمرکز کرد که در پاس اول کم‌بررسی مانده بودند: مسیر آپدیتر، قفل‌های
هم‌زمانی، سطح مجوزهای IPC و CSS. ۸ یافتهٔ دیگر پیدا شد.

## باگ‌ها

### B13 — نوشتن دیسک در هر تغییر تم، آن هم زیر قفل — **متوسط**

`apply_profile_inner` مقدار `last_active_profile` را در کانفیگ می‌نوشت و `config.save()` را
**داخل محدودهٔ `config.lock()`** صدا می‌زد. یعنی هر کلیک روی آیکون tray:
- یک نوشتن فایل (سریالایز JSON + tmp + rename) انجام می‌داد،
- و در همان حال قفل کانفیگ را نگه می‌داشت، پس `get_app_state` (باز شدن پنل) و `save_settings`
  می‌توانستند پشت آن منتظر بمانند.

و نکتهٔ اصلی: `last_active_profile` **هیچ‌جا خوانده نمی‌شد**. یک فیلد کاملاً مرده بود.

**رفع:** فیلد از struct، تایپ‌های فرانت‌اند و mock حذف شد؛ نوشتن دیسک در مسیر apply کاملاً حذف شد.
تست جدید `unknown_fields_from_older_configs_are_ignored` تأیید می‌کند کانفیگ‌های قدیمی که این فیلد
(و فیلدهای v1) را دارند همچنان بدون خطا لود می‌شوند.

### B14 — `toggle_autostart_inner` قبل از نوشتن رجیستری state را عوض می‌کرد — **متوسط**

مقدار در حافظه اول flip می‌شد، بعد Run key نوشته می‌شد. اگر نوشتن رجیستری شکست می‌خورد (سیاست
سازمانی/آنتی‌ویروس)، تابع `Err` برمی‌گرداند ولی حافظه می‌گفت autostart روشن است و فایل ذخیره هم
نمی‌شد → تا ری‌استارت بعدی ناسازگاری. (آینهٔ همان باگی که در B4 برای `save_settings` رفع شد.)

**رفع:** اول مقدار جدید فقط *خوانده* می‌شود، بعد رجیستری نوشته می‌شود، و تنها در صورت موفقیت حافظه
به‌روز و فایل (بیرون از قفل) ذخیره می‌شود.

### B15 — کلیک روی پنل می‌توانست بی‌صدا دور ریخته شود — **پایین**

اگر یک apply در جریان بود (مثلاً کلیک هم‌زمان روی tray و روی پنل)، `apply_profile` بلافاصله
`read_theme_state()` برمی‌گرداند: یعنی کلیک دوم انجام نمی‌شد و UI وضعیت کلیک *دیگر* را نشان می‌داد.

**رفع:** تا ۲۵ms (۵ گام ۵ میلی‌ثانیه‌ای) برای آزاد شدن گارد صبر می‌کند و بعد یک بار دیگر تلاش می‌کند.
مقدار ۲۵ms عمداً کوتاه است چون این تابع روی main thread اجرا می‌شود و انتظار طولانی پنل را فریز می‌کرد.

## امنیت / حداقل دسترسی

### S4 — سطح IPC و مجوزها بیش از نیاز بود — **پایین**

- کامند `hide_panel` هیچ‌جا از UI صدا زده نمی‌شد (دکمهٔ ✕ از `window.close()` استفاده می‌کند).
- مجوزهای `core:window:allow-hide`، `allow-show` و `allow-set-focus` هم بی‌استفاده بودند؛
  `hide/show/set_focus` فقط از سمت Rust صدا زده می‌شوند که به مجوز JS نیازی ندارد.

**رفع:** کامند، متد `api.hidePanel` و سه مجوز حذف شدند. سطح حملهٔ IPC کوچک‌تر شد.

## بهینه‌سازی / کیفیت

### O5 — CSS: سرریز متن خطا و انیمیشن اجباری

- ارتفاع پنل ۲۳۲ است و `overflow: hidden` روی html/body؛ یک پیام خطای طولانی می‌توانست فوتر را
  بیرون از کادر هل بدهد. حالا با `-webkit-line-clamp: 2` بریده می‌شود.
- `@media (prefers-reduced-motion: reduce)` اضافه شد تا انیمیشن‌ها با تنظیمات دسترس‌پذیری کاربر
  خاموش شوند.

### O6 — قواعد مردهٔ `data-theme`

`public/boot.css` قواعد `html[data-theme="dark"]` داشت، ولی هیچ‌جای نسخهٔ ۲ صفت `data-theme` را
تنظیم نمی‌کند (میراث v1). حذف شد؛ تنها منبع تم `prefers-color-scheme` است.

### O7 — واریانت‌های بی‌استفادهٔ `ErrorCode`

`Broadcast` و `Updater` هیچ‌جا ساخته نمی‌شدند؛ حذف شدند.

### O8 — کامنت کهنه

کامنت بالای `global.css` می‌گفت «۳۴۰×۲۴۶» در حالی که پنل ۳۴۰×۲۳۲ است.

## مواردی که بررسی شد و مشکلی نداشت

| مورد | نتیجه |
|---|---|
| تعامل آپدیتر با `ExitRequested` (که برای tray `prevent_exit` می‌کند) | پلاگین روی ویندوز مستقیماً `std::process::exit(0)` صدا می‌زند، پس گارد ما آپدیت را بلاک نمی‌کند. |
| `apply_profile` هم‌زمان از tray و IPC | با گارد RAII + تلاش دوباره پوشش داده شد (B15). |
| چک آپدیت در هر باز شدن پنل | یک GET کوچک (~۸۰۰ بایت) و خطاها بی‌اثرند؛ throttle اضافه نشد چون نیازمند state سمت Rust یا سطح IPC بیشتر بود و سودش ناچیز است. |
